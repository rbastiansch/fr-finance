# Accessing the VM

This guide describes how to connect to the deployment VM over SSH. Keep the
private key outside the repository and never commit it to Git.

## Prerequisites

- The VM has a public IP address.
- The VM's network security group or security list allows TCP port `22` from
  your current public IP address.
- You have the private SSH key that matches the public key added to the VM.

## Connect with SSH

Restrict the private key permissions before using it:

```sh
chmod 600 /path/to/private-key.key
```

Connect to an Ubuntu VM:

```sh
ssh -o IdentitiesOnly=yes \
  -i /path/to/private-key.key \
  ubuntu@<VM_PUBLIC_IP>
```

The key can also use read-only permissions:

```sh
chmod 400 /path/to/private-key.key
```

Do not use `sudo` to run the SSH command. The private key should be owned and
readable by your local user only.

## Common connection errors

### `Load key ...: bad permissions`

The private key is readable by other users. Run:

```sh
chmod 600 /path/to/private-key.key
```

### `Permission denied (publickey)`

Check that:

- The SSH username matches the image (`ubuntu` for Ubuntu or `opc` for Oracle Linux).
- The private key matches the public key added when the VM was created.
- The `-i` option points to the intended private key.

### Connection timeout

Check that:

- The VM has a public IP address.
- TCP port `22` is allowed from your IP in the OCI network security group or
  subnet security list.
- The VM is in a public subnet with a route to an Internet Gateway.

## Access without a public IP

Use an OCI Bastion managed SSH session. Create the Bastion in the same VCN,
create a session for the VM, and run the SSH command generated by OCI. Bastion
sessions provide temporary access without exposing the VM directly to the
internet.
